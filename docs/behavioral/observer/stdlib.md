# 14.3 Go 里的观察者

## 用函数当观察者

观察者只有一个方法时，Go 里常直接用[回调函数](../../appendix/callbacks.md)，省掉接口和类型。订阅时返回一个**取消函数**，调用它就退订：

```go
--8<-- "codes/behavioral/observer/bus.go:bus"
```

用法：`cancel := bus.On(func(o Order) { ... })`，不再需要时 `cancel()`。取消用的是指针比较，所以不怕两个函数长得一样。

## 标准库中的观察者

| 位置 | 订阅什么 | 怎么退订 |
|---|---|---|
| `signal.Notify`（`os/signal`） | 系统信号（如 Ctrl+C），送到你给的 channel | `signal.Stop` |
| `context.AfterFunc`（Go 1.21） | `ctx` 被取消时，调用你给的函数 | 返回的 `stop()` |
| `http.Server.RegisterOnShutdown` | 服务器关闭时，调用你给的函数 | 无 |

`context.AfterFunc` 和上面的 `Bus.On` 一样，返回一个退订函数，这是 Go 里最常见的写法。

## 观察者与发布-订阅

| | 观察者 | 发布-订阅 |
|---|---|---|
| 中间有没有第三方 | 没有，主题直接调用观察者 | 有消息中间件（如 Kafka、NATS） |
| 双方是否知道彼此 | 主题持有观察者列表 | 互不知道，只认主题名 |
| 同步还是异步 | 通常同步，在同一进程内 | 通常异步，可跨进程、跨机器 |

## 什么时候用

<div class="grid" markdown>

!!! success "适合"

    - 一件事发生后，多个模块要各自响应
    - 接收方会增减，不想每次都改发出方
    - 希望在运行时动态订阅、退订

!!! failure "不适合"

    - 只有一个固定的接收方，直接调用更清楚
    - 接收方的执行顺序很重要，或彼此依赖
    - 通知链层层触发，出问题时难以追踪是谁调用了谁

</div>
