# 17.4 小结

## 重点回顾

!!! takeaway "划重点"
    - 责任链 = **处理者串成一条链**，请求从链头进入，处理不了就交给下一个。
    - 发送方只认识链头；加一环、换顺序、调规则，只改串链的地方。
    - 链尾要有兜底：没人能处理时，明确返回「无人处理」或错误，不要静默丢掉。

## Q & A

**Q**：如果链上没有人能处理，会怎样？

请求会走到链尾。本例在 `Next == nil` 时返回「无人能批」；也可以在链尾放一个专门的兜底处理者，或返回 `error`。千万别什么都不返回，否则调用方以为已经处理好了。

**Q**：链太长会不会慢？

没人接手时会走完整条链。耗时主要看各环做了什么，例如每环都查数据库就会累加等待时间。排查时可以记录尝试过的处理者，看看请求停在哪一环。

**Q**：处理者能不能「处理一部分，再交给下一个」？

可以，这就是中间件的写法：每一环都做点事（记日志、鉴权），然后调用下一环。经典责任链找到处理者就停；中间件通常继续转发，也可以因鉴权失败等原因提前返回，见 [17.3](stdlib.md)。

**Q**：用 `Next` 字段串链，还是用切片？

处理者需要自己决定「要不要往下传」（比如中间件可以提前拦截）时，用 `Next`；规则只是「依次试，第一个成功的说了算」时，用函数切片更短，处理者之间也互不依赖。
