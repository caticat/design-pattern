# 17.3 Go 里的责任链

## 用函数切片串链

不想给每个处理者都定义类型和 `Next` 字段时，可以把每一环写成函数，放进切片按顺序试：

```go
--8<-- "codes/behavioral/chain/first.go:first"
```

链的顺序就是参数的顺序，`First(small, large)` 先试 `small` 再试 `large`。处理者之间**互不引用**，增删一环只改这一行调用。

## 标准库中的责任链

| 位置 | 链上传的是什么 | 怎么往下传 |
|---|---|---|
| `context.Context` 的 `Value` | 按 key 查值 | 自己没有这个 key，就问父 `Context` |
| `errors.Is`、`errors.As` | 匹配目标错误或类型 | 沿 `Unwrap` 逐层找；有多个子错误时，按深度优先查找 |
| `net/http` 中间件 | HTTP 请求 | 可调用 `next.ServeHTTP` 放行，也可提前返回 |

## 两种链、两个近亲

| | 关键区别 |
|---|---|
| 经典责任链 vs 中间件 | 经典责任链**找到一个处理者就停**；中间件可以先做自己的工作，再把同一个请求往下传 |
| 责任链 vs [装饰器](../../structural/decorator/index.md) | 结构相似，都是一层套一层；装饰器每层都**加功能**，责任链是**选出谁来处理** |

## 什么时候用

<div class="grid" markdown>

!!! success "适合"

    - 多个对象都可能处理请求，事先不知道是哪一个
    - 处理者和顺序需要灵活调整（审批流、过滤器、校验规则）
    - 想让发送方和处理方解耦，发送方只认识链头

!!! failure "不适合"

    - 只有一两种情况，`if` 或 `switch` 一眼看完
    - 必须保证有人处理，又容易漏配链尾（要加兜底处理）

</div>
