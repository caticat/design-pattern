# 易混模式对比

有些模式代码长得几乎一样，区别在**用意**。下面把最常混淆的几组放在一起，每组末尾给一句判断方法。各章小结的 Q & A 有更多细节。

## 包一层：适配器、装饰器、代理、外观 { #wrappers }

| 模式 | 对外接口 | 包住几个对象 | 目的 | 被包对象从哪来 |
|---|---|---|---|---|
| [适配器](structural/adapter/index.md) | **变**成调用方要的接口 | 一个 | 让不兼容的类型能用 | 外部传入 |
| [装饰器](structural/decorator/index.md) | 不变 | 一个，可层层叠加 | 在结果上**多做点什么** | 外部传入 |
| [代理](structural/proxy/index.md) | 不变 | 一个，通常只一层 | **控制访问**：权限、缓存、延迟加载 | 常由代理自己创建 |
| [外观](structural/facade/index.md) | **新设计**一个简单接口 | 一组子系统 | 给复杂子系统一个入口 | 外观自己组装 |

==接口变了是适配器；接口不变、多做事是装饰器，管能不能做是代理；面对一整组子系统是外观==。

## 换一种做法：策略、状态、模板方法、桥接、命令 { #behaviors }

| 模式 | 替换的是什么 | 谁来切换 | 典型信号 |
|---|---|---|---|
| [策略](behavioral/strategy/index.md) | **整个**算法 | 使用方从外部选 | 同一件事有多种算法，按配置选 |
| [状态](behavioral/state/index.md) | 当前阶段的行为 | 对象处理事件后**自己**切换 | 「现在能做什么、做完去哪」随阶段变化 |
| [模板方法](behavioral/template-method/index.md) | 固定流程中的**某几步** | 写代码时定好 | 几个流程顺序相同，只有个别步骤不同 |
| [桥接](structural/bridge/index.md) | 底层实现（如发送渠道） | 组装时传入 | 两个维度**都**有多个变体，避免每处都写 `switch` |
| [命令](behavioral/command/index.md) | 不替换，而是把「一件待执行的事」存起来 | 调用方决定何时执行 | 要排队、延后执行、记录或撤销 |

判断方法：先问「换的是整套还是几步」——整套是策略，几步是模板方法；再问「谁来换」——外部选是策略，自己变是状态；持有接口的一边也有多个变体时是桥接。

## 创建对象：单例、工厂方法、抽象工厂、建造者、原型 { #creators }

| 模式 | 解决的问题 | 产出 | 一句话 |
|---|---|---|---|
| [单例](creational/singleton/index.md) | 全程只要一个实例 | 同一个对象 | 只创建一次 |
| [工厂方法](creational/factory-method/index.md) | 流程固定，创建方式要可换 | **一种**产品 | 留一个创建扩展点 |
| [抽象工厂](creational/abstract-factory/index.md) | 一组对象必须配套 | **一族**产品 | 成套地换 |
| [建造者](creational/builder/index.md) | 一个对象参数多、要分步组装 | **一个**复杂对象，最后才返回 | 一步步拼 |
| [原型](creational/prototype/index.md) | 按已有对象再造一个 | 已有对象的副本 | 复制，运行时就能加新品种 |

判断方法：要配套用抽象工厂，要分步用建造者，要照着现成的复制用原型，只是让创建可替换用工厂方法。

## 树与遍历：组合、迭代器、访问者、解释器 { #trees }

| 模式 | 关注点 | 一句话 |
|---|---|---|
| [组合](structural/composite/index.md) | 叶子和容器**统一对待** | 把对象组成树，整体和部分同一个接口 |
| [迭代器](behavioral/iterator/index.md) | **按什么顺序**取下一个元素 | 遍历方式与集合结构分开 |
| [访问者](behavioral/visitor/index.md) | 对每个元素**做什么** | 不改元素类型，加新操作 |
| [解释器](behavioral/interpreter/index.md) | 树的每种节点**代表什么含义** | 在组合式的树上规定文法和求值 |

四者常一起出现：组合搭出树，迭代器决定遍历顺序，访问者在遍历时处理每个节点，解释器给语法树赋予含义。和装饰器的区别：装饰器只包**一个**对象，组合持有**多个**子节点并汇总结果。

## 对象之间传消息：观察者、中介者、责任链、外观 { #messaging }

| 模式 | 消息方向 | 谁决定怎么处理 | 一句话 |
|---|---|---|---|
| [观察者](behavioral/observer/index.md) | 一对多广播 | 每个订阅者自己决定 | 一处变化，通知所有关心的人 |
| [中介者](behavioral/mediator/index.md) | 多对多，经过中间人 | 中介者统一协调 | 对象之间不直接联系 |
| [责任链](behavioral/chain-of-responsibility/index.md) | 沿链依次传递 | 链上第一个能处理的 | 发送方不知道最终谁处理 |
| [外观](structural/facade/index.md) | 单向：调用方 → 子系统 | 外观按固定步骤调 | 子系统不认识外观 |

判断方法：通知完就不管是观察者；收到通知后还要协调别人怎么动是中介者；只要一个人处理、但不知道是谁时是责任链。

## 撤销：命令与备忘录 { #undo }

| 模式 | 保存的是 | 撤销方式 |
|---|---|---|
| [命令](behavioral/command/index.md) | 「做了什么」 | 执行反向操作或补偿操作 |
| [备忘录](behavioral/memento/index.md) | 「原来是什么」 | 恢复之前的快照 |

两者可以配合：命令执行前先存一份备忘录，撤销时恢复它。
