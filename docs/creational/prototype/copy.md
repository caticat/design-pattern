# 5.3 深拷贝与标准库

## 只复制一层会怎样

如果 `Clone` 只写 `c := *m`：

```go
--8<-- "codes/creational/prototype/bad.go:shallow"
```

改副本，原型也被改了：

```go
--8<-- "codes/creational/prototype/prototype_test.go:shallow-demo"
```

只有 `Name` 没被改到。切片、map、指针字段里存的只是「指向数据的引用」，复制一层只复制了引用，两个对象**共用同一份数据**。这叫**浅拷贝**；把引用指向的数据也复制一份，叫**深拷贝**。

![左：两只手办牵着同一个气球，吉祥物把它涂成青色，两只的气球都变了；右：两只手办各牵一个气球，只有一个被涂成青色](../../assets/images/prototype-copy.webp){ .illus }

<p class="caption">浅拷贝的两个对象共用一个气球，涂一个两边都变；深拷贝各有一个，互不影响</p>

`c := *m` 之后，各类字段的情况：

| 字段类型 | 复制一层后 | 深拷贝怎么做 |
|---|---|---|
| 数字、bool、string | 值可独立使用；字符串不可变 | 无需处理 |
| 数组、结构体 | 元素或字段按值复制，内部仍可能共享可变数据 | 检查元素和字段，按需复制其中的可变数据 |
| 切片 | 共用底层数组 | `slices.Clone` |
| map | 共用同一个 map | `maps.Clone` |
| 指针 | 指向同一个对象 | 复制指向的值，再取地址 |
| 接口 | 复制接口值；如果它装着指针等引用，仍可能共享可变数据 | 按接口中的实际类型判断 |
| chan、函数 | 仍操作同一个 channel；闭包仍引用原来的变量 | 不做通用深拷贝 |

`slices.Clone`、`maps.Clone` 本身也只复制一层：元素如果又是指针、切片或 map，还要逐个复制。

## 标准库中的 Clone

| 方法 | 复制深度 |
|---|---|
| `slices.Clone`、`maps.Clone`、`bytes.Clone` | 复制一层：容器独立，元素按值复制 |
| `http.Header.Clone()` | 深拷贝：每个键对应的 `[]string` 也复制 |
| `(*http.Request).Clone(ctx)` | 深拷贝大部分字段，请求体 `Body` 仍然共用 |
| `(*tls.Config).Clone()` | 浅拷贝：证书等引用类型字段仍然共用 |

标准库的 `Clone` 深浅不一，用之前先看文档里写的是哪一种。

## 什么时候用

<div class="grid" markdown>

!!! success "适合"

    - 大量相似对象，只差少数几项
    - 对象的初始配置很繁琐，或依赖运行时加载的数据
    - 想在修改前留一份快照，出错时还原

!!! failure "不适合"

    - 字段少，直接写构造函数更清楚
    - 对象含有难以复制的资源（打开的文件、网络连接、锁）
    - 对象之间互相引用成环，深拷贝写起来复杂又容易漏

</div>
