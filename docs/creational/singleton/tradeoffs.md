# 1.3 单例与全局变量

## 区别在于「是否受控」

单例和全局变量都是「全局都能拿到的一份数据」，区别在于**创建和替换是否受控**：

![左：放在开放架子上的钟被机械臂换掉；右：钟锁在柜子里，只从一个窗口发放](../../assets/images/singleton-compare.webp){ .illus }

<p class="caption">全局变量谁都能换掉；单例把实例锁起来，只留一个访问窗口</p>

| | 全局变量 `var Cfg = &Config{}` | 单例 `GetInstance()` |
|---|---|---|
| 唯一性 | 不保证：谁都能 `Cfg = &Config{}` 换掉 | 保证：变量不导出，只能经访问函数获取 |
| 创建时机 | 包初始化时，用不用都创建 | 首次调用时（延迟加载） |
| 并发创建 | 不涉及（初始化阶段单线程） | `sync.Once` 保证只创建一次 |
| 共同缺点 | 全局状态：依赖关系隐式、测试互相影响 | 同左 |

## 标准库中的单例

Go 标准库很少「强制单例」，更常见的是**默认实例**：提供一个开箱即用的全局实例，同时允许使用者自己创建。

| 例子 | 做法 |
|---|---|
| `mime.TypeByExtension` | 首次调用时用 `sync.Once` 加载系统 MIME 类型表，之后复用 |
| `time.Local` | 本地时区信息在首次使用时通过 `sync.Once` 懒加载 |
| `http.DefaultClient`、`slog.Default()` | 全局共享的「默认那一个」，但仍可自己创建（`&http.Client{}`、`slog.New`） |

## 什么时候用

判断顺序：先问「必须全局只有一份吗」，再问「能不能通过参数传进来」——能传参就传参，两者都不行才用单例。

<div class="grid" markdown>

!!! success "适合"
    - 真正全局唯一的资源：配置、日志器、连接池
    - 创建代价高，希望按需延迟加载
    - 实例无状态或只读

!!! failure "不适合"
    - 只是为了「到处都能拿到」而图省事
    - 需要多份隔离实例（多租户、多数据库）
    - 单元测试需要替换成假对象

</div>
