# 8.3 代理的用途

## 常见的几种代理

结构都一样：同一个接口，先做点什么，再转交。区别只在「先做的那件事」：

| 种类 | 代理先做什么 | 例子 |
|---|---|---|
| 虚拟代理 | 第一次需要时才创建真实对象 | 本章的 `VideoProxy`、大图片懒加载 |
| 保护代理 | 检查调用方有没有权限 | 会员才能看、管理员才能删 |
| 缓存代理 | 结果已经有了就直接返回 | 查询结果缓存 |
| 远程代理 | 把调用变成网络请求，发给另一台机器 | gRPC 生成的客户端 |
| 日志代理 | 记录调用参数、耗时 | 访问日志、监控埋点 |

本章的 `VideoProxy` 同时是虚拟代理和保护代理。

## 标准库与常用库中的代理

| 位置 | 是哪种代理 |
|---|---|
| `httputil.ReverseProxy`（`net/http/httputil`） | 远程代理：本身是 `http.Handler`，把收到的请求转发给后端服务器，用 `Rewrite` 改写请求 |
| gRPC 生成的 `XxxClient`（`google.golang.org/grpc`，非标准库） | 远程代理：调用起来像本地方法，实际发出网络请求 |
| `sync.OnceValue`（Go 1.21） | 不是代理本身，但写虚拟代理时常用它做并发安全的延迟创建 |

`ReverseProxy` 和真实服务器对浏览器来说是同一个接口（都是 HTTP），浏览器分不出中间多了一层：

```mermaid
flowchart LR
    B[浏览器] -->|请求| P[ReverseProxy<br>Rewrite 改写目标]
    P -->|转发| S[后端服务器]
    S -.->|响应| P
    P -.->|原样返回| B
```

<p class="caption">浏览器只和代理打交道，代理替它把请求转给后端</p>

## 代理和装饰器

两者结构几乎一样，都是「同一个接口 + 持有另一个对象」，区别在用意：

| | 代理 | 装饰器 |
|---|---|---|
| 目的 | **控制访问**：能不能用、什么时候创建 | **叠加功能**：在原有结果上多做一点 |
| 真实对象由谁创建 | 通常代理自己创建、管理 | 调用方创建好，传进来包装 |
| 层数 | 通常只有一层 | 常常一层套一层 |

## 什么时候用

<div class="grid" markdown>

!!! success "适合"

    - 真实对象创建昂贵，又不一定用得到
    - 访问前要统一检查权限，不想让每个调用方自己写
    - 想让调用方像调用本地对象一样调用远程服务

!!! failure "不适合"

    - 对象创建很便宜，也没有访问限制，多一层只是绕路
    - 只想多加点功能，用装饰器更直接
    - 对性能极其敏感的热点路径，每次多一次转交

</div>
