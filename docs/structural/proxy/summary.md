# 8.4 小结

## 重点回顾

!!! takeaway "划重点"
    - 代理 = **同一接口的替身**，挡在真实对象前面控制访问。
    - 代理先做检查、延迟创建或缓存，再把调用转交给真实对象。
    - 调用方只依赖接口，换成代理不用改一行调用代码。

## Q & A

**Q**：代理和适配器有什么区别？

适配器**改变接口**，把不兼容的类型转成调用方要的样子；代理**接口不变**，只控制能不能、什么时候访问真实对象。

**Q**：代理和装饰器写出来几乎一样，怎么区分？

看用意：代理管「能不能用、何时创建」，真实对象通常由代理自己创建；装饰器管「多做点什么」，被包装的对象由调用方传入，可以层层叠加。对比表见 [8.3](uses.md)。

**Q**：延迟加载怎么做到并发安全？

把 `real *HDVideo` 换成 `load func() *HDVideo`，在 `NewVideoProxy` 里写 `load: sync.OnceValue(func() *HDVideo { return LoadHDVideo(title) })`，`Play` 里调用 `p.load()`。多个 goroutine 同时调用，也只会加载一次（见[附录 A](../../appendix/concurrency.md)）。

**Q**：一定要先定义接口吗？

调用方要能「分不出是代理还是真实对象」，就需要接口。Go 的接口是隐式实现的，即使真实类型来自别的包，也可以在调用方这边定义一个只含所需方法的小接口，再让代理实现它。
