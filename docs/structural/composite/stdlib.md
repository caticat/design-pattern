# 10.3 Go 里的组合

## error 也是一棵树

Go 1.20 起，`errors.Join` 能把多个错误组合成一个，组合出来的仍然是 `error`：

```go
--8<-- "codes/structural/composite/stdlib.go:errors"
```

和目录一样：调用方拿到的可能是一个错误，也可能是一组，用法不变。`errors.Is` 就是那个「一层层往下问」的递归。

## 标准库中的组合

| 位置 | 叶子和组合 | 统一的操作 |
|---|---|---|
| `errors.Join`、多个 `%w` 的 `fmt.Errorf` | 普通错误 / 组合错误 | `errors.Is`、`errors.As` 遍历整棵树 |
| `io/fs` | 文件 / 目录，都是 `fs.DirEntry` | `fs.WalkDir` 递归遍历 |
| `go/ast` | 标识符 / 函数、语句块，都是 `ast.Node` | `ast.Inspect` 遍历语法树 |
| `testing` 的 `t.Run` | 子测试 / 父测试 | 子测试全部通过，父测试才通过 |

## 透明还是安全

`Add` 放在哪里，有两种做法：

| | 透明：`Add` 放进 `Node` 接口 | 安全：`Add` 只放在 `Dir` 上 |
|---|---|---|
| 好处 | 叶子和组合完全一样，调用方从不区分 | 文件根本没有 `Add`，误用编译不过 |
| 代价 | 文件也得实现 `Add`，只能报错或什么都不做 | 要加子节点时，得拿到 `*Dir` |

Go 里通常选**安全**：接口越小越好，本章的 `Node` 只有读的方法。

## 什么时候用

<div class="grid" markdown>

!!! success "适合"

    - 数据天然是树：目录、菜单、组织架构、界面控件、语法树
    - 希望调用方不区分单个对象和一组对象
    - 对整棵树做统计、渲染、查找这类递归操作

!!! failure "不适合"

    - 数据不是树，只有一层列表，切片就够了
    - 叶子和组合能做的事差别很大，硬凑一个接口反而别扭
    - 树很深又在热点路径上，递归调用的开销不可忽视

</div>
