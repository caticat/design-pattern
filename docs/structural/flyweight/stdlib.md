# 12.3 Go 里的享元

## unique：标准库自带的享元工厂

Go 1.23 新增的 `unique` 包，专门做「相同的值只存一份」：

```go
--8<-- "codes/structural/flyweight/stdlib.go:unique"
```

`unique.Make` 就是一个通用、并发安全的享元工厂：内容相同就返回同一个句柄，比较时只比一个指针，没人引用后还会被 GC 回收。字符串大量重复时（如日志里的城市名、标签），用它能省下不少内存。

## 标准库中的享元

| 位置 | 共享的是什么 |
|---|---|
| `unique.Make`（Go 1.23） | 任意可比较的值，相同的只存一份 |
| `net/netip.Addr` | IPv6 地址的区域名（zone）用 `unique` 存，大量地址共用一份 |
| `reflect.TypeOf` | 同一类型总返回同一个 `Type`，可直接用 `==` 比较 |

## 享元、对象池与单例

三者都在「复用对象」，复用的方式不同：

| | 享元 | `sync.Pool` 对象池 | 单例 |
|---|---|---|---|
| 怎么共享 | 多处**同时**用同一个 | 用完归还，**轮流**用 | 全局只有一个 |
| 对象能否修改 | 不可变 | 可变，取出后要重置 | 通常可变 |
| 有几个 | 每种内部状态一个 | 不定，GC 时可能清空 | 一个 |
| 目的 | 省内存 | 减少分配、减轻 GC | 全局唯一 |

## 什么时候用

<div class="grid" markdown>

!!! success "适合"

    - 对象数量极多，且大部分数据重复
    - 重复的部分能做成不可变
    - 用 pprof 确认过内存确实花在这些重复数据上

!!! failure "不适合"

    - 对象不多，省下的内存微不足道
    - 共享的部分需要各自修改
    - 拆出外部状态后，调用方传参变得繁琐，得不偿失

</div>
