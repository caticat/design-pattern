# 写作规范与章节模板

## 写作原则

- **图先行**：章首一张类比大图建立直觉；N.1 必有一张过程插图展示「问题 → 解决」，其余小节只在图能讲清结构、行为或顺序时配图，小结默认不加图。插图贴着对应说明，不能隔开示例代码与运行按钮。
- **短**：一页（一节）正文 300–700 字，渲染后不超过约 2 屏；段落不超过 4 行；能用表格不用段落。
- **一件事只讲一遍**：同一结论只用一种形式表达（插图 / Mermaid / 表格选一），不在多节重复；进阶细节和其它语言的写法放小结 Q & A。
- **基础知识放附录**：跨章复用的 Go 基础（如并发）写在 `docs/appendix/`，正文首次出现时用括号给一句白话并链接附录；不用折叠块。附录页不编章号、不要求配图。读类图、术语这类全书通用的说明也放附录（附录 D、E）；易混模式的横向对比集中在 `docs/compare.md`，各章 Q & A 只讲本章视角。
- **一章一个模式**：其它模式只在小结 Q&A 中一两句带过。
- **术语**：首次出现写「中文（English）」，之后只用中文。
- **不编造**：标准库 / 开源项目实例必须真实存在，写出包名和类型/函数名，可在 pkg.go.dev 查证。
- **不过时**：讲原理，不追新版本特性；用到 Go 1.21+ 特性时注明版本。
- **语气**：直接陈述，不用「我们来看看」「众所周知」等填充语。

## 篇章结构（参照 hello-algo）

- **篇** = 模式分类（创建型 / 结构型 / 行为型），导航分组。
- **章** = 一个模式，全书统一编号；一章 = 一个目录，含章首页 + 4 节。

| 篇 | 章号与模式 |
|---|---|
| 创建型 | 1 单例、2 工厂方法、3 抽象工厂、4 建造者、5 原型 |
| 结构型 | 6 适配器、7 装饰器、8 代理、9 外观、10 组合、11 桥接、12 享元 |
| 行为型 | 13 策略、14 观察者、15 模板方法、16 迭代器、17 责任链、18 命令、19 状态、20 备忘录、21 中介者、22 访问者、23 解释器 |

**样板章：`docs/creational/singleton/`**。新章节照它的结构与组件写。

```text
docs/<分类>/<模式>/
  index.md            章首页：标题 + 信息条 + 封面大图 + 题记 + 本章内容 + 前置知识 / 相关对比
  problem.md          N.1 问题与思路：过程插图 → 反例 → 出错过程图 → 解决思路 → 类图（≥2 个类型时）+ 角色表
  implementation.md   N.2 Go 实现：代码 + 使用示例 + Playground（全章唯一）+ 写法选择
  <topic>.md          N.3 专题：与相近写法/模式的对比、标准库实例、什么时候用（文件名按主题取）
  summary.md          N.4 小结：重点回顾 + Q & A + 动手试试
```

`mkdocs.yml` 导航：章标题写 `第 N 章 &nbsp; X 模式`，节只列文件不写标题（节标题取各页 H1）。

## 页面模板

### 章首页 `index.md`

```markdown
# X 模式

<div class="pattern-meta" markdown>
<span>:material-shape-outline: 创建型</span>          <!-- 创建型 / 结构型 / 行为型 -->
<span>:material-signal-cellular-1: 难度 入门</span>   <!-- 入门 cellular-1 / 进阶 cellular-2 / 较难 cellular-3 -->
<span>:material-fire: 使用频率 高</span>              <!-- 高 / 中 / 低 -->
</div>

![<图名>](../../assets/images/<模式>.webp){ .cover }

!!! abstract ""

    <一句生活类比，与封面图对应>

    X 模式<意图，一句话，关键词加粗>。

## 本章内容

| 节 | 内容 |
|---|---|
| [N.1 问题与思路](problem.md) | … |
| [N.2 Go 实现](implementation.md) | … |
| [N.3 <专题>](<topic>.md) | … |
| [N.4 小结](summary.md) | 重点回顾、常见问题与动手试试 |

**前置知识**：[附录 B 接口与方法](../../appendix/interfaces.md) · [附录 D 怎么读类图](../../appendix/class-diagram.md)　**相关对比**：[包一层](../../compare.md#wrappers)
```

最后一行：「前置知识」列本章示例用到的附录（有类图的章加附录 D），「相关对比」链接 `docs/compare.md` 中本模式所在的组；两项都没有就省略这一行。

### 节页面

- H1 带节号：`# N.1 问题与思路`；节内用 H2 分 2–3 段，不用 H4。
- 反例与正解代码全部 snippets 引用 `codes/`。
- 每张 Mermaid 图下方写图注（见下），图注一句话说清图想表达的结论。
- 小结页：`## 重点回顾`（一个 `!!! takeaway "划重点"`，≤3 条）+ `## Q & A`（3–5 个，格式 `**Q**：问题？` 换行后直接写答案）+ `## 动手试试`（2 题：一题照本章结构扩展一种实现，一题动手验证一个易错点）。
- 动手试试格式：`1. **任务名**：要求。` 换行缩进写 `提示：…。检验：…。`；每题须实际做过一遍，确认只改读者自己的代码就能完成、检验结果可复现。

### 图注

```markdown
<p class="caption">一句话结论</p>
```

由 `hooks/captions.py` 按章自动编号为「图 N-k」（跨节连续），不要手写编号。章首封面图不写图注。

## 视觉组件用法

| 组件 | 用途 | 限制 |
|---|---|---|
| `pattern-meta` 信息条 | 分类 / 难度 / 使用频率 | 只在章首页 |
| `{ .cover }` 封面图 | 章首类比大图 | 只在章首页，每章一张 |
| `{ .illus }` 过程插图 | 三步条 / 左右对比，见 `spec/image.md` | 问题节必有，其余按需，下方必有图注 |
| `!!! abstract ""` 题记 | 类比 + 一句话定义 | 只在章首页 |
| `<p class="caption">` | 图注 | 每张正文图都要有 |
| `==文字==` 荧光笔 | 全章最关键的一句 | 每章 1–2 处 |
| `=== "标签"` | 多种等价写法 | 默认标签放最易懂的写法 |
| `!!! tip` / `!!! warning` / `!!! bug` | 易错点 | 每节不超过 1 个 |
| `grid` + success/failure | 适合 / 不适合 | 放在专题节「什么时候用」 |
| `!!! takeaway` | 重点回顾（带吉祥物） | 只在小结页 |

- **不用折叠块**（`???`）：内容要么值得放在正文，要么删掉；提示框内**不放表格**（避免框套框）。
- 不新增自定义样式；确需新组件时先改样板章与本表，再推广。

## 代码引用

- 正文代码**全部**通过 snippets 引用 `codes/` 下的文件，不手写代码块（保证代码可编译、可测试）。
- 引用整文件：`--8<-- "codes/creational/singleton/singleton.go"`
- 引用片段：源码中用 `// --8<-- [start:name]` / `// --8<-- [end:name]` 标记，正文写 `--8<-- "path.go:name"`。
- 在线运行：每章一个 Playground 按钮，只放在 N.2 Go 实现页（附录页也可各放一个），该页只引用一个代码包：

    ```markdown
    [:material-play: 在 Go Playground 运行](https://go.dev/play/p/TODO){ .md-button .md-button--primary target=_blank } [:material-github: 查看完整源码](https://github.com/caticat/design-pattern/tree/master/codes/<分类>/<包>){ .md-button target=_blank }
    ```

    按钮**紧跟在它运行的示例代码块之后**（中间不插图、不插文字），样式会自动拼成代码块底部的工具栏；该节插图放在代码之前。Playground 从公共仓库拉取模式包，故代码改动后须**先提交并推送**，再运行 `python -I scripts/playground.py --update` 刷新链接并提交；不带参数为离线校验。

## 自检清单（提交人工审查前逐条确认）

- [ ] 封面图与题记类比对应；一句话定义准确
- [ ] 过程插图与封面沿用同一隐喻，N.1 有「问题 → 解决」插图
- [ ] 反例能说明痛点，方案确实解决了该痛点
- [ ] 类图角色与代码中的类型名一致
- [ ] 标准库实例真实存在（已核对包名/类型名）
- [ ] 每节字数在范围内、不超过约 2 屏，无填充语、无重复
- [ ] 每张正文图都有图注，编号连续
- [ ] 章首页有前置知识 / 相关对比行，N.2 有源码按钮；小结有 2 道已验证的动手试试
- [ ] 新模式加入 `patterns.md` 的「按问题查」表；与已有模式易混时，在 `compare.md` 补一行
- [ ] `go test ./...`、`go vet ./...`、`mkdocs build --strict`、`python -I scripts/playground.py` 全部通过
- [ ] 本地页面渲染正常（Mermaid、图片、标签页），浅色 / 深色模式都看过
